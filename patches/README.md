# Dependency patches

`@sqlite.org__sqlite-wasm@3.53.4-build1.patch` aligns the legacy worker's proxy construction with the primary initializer's static proxy asset URL. Turbopack otherwise treats its dynamic URL as a worker module dependency and fails compilation even when only the package's default SQLite initializer is used. Mail search uses SAHPool; the legacy proxy is not instantiated by the application. Remove after upgrading to a release with the same bundler-compatible legacy worker implementation, and validate with the emulated local search browser suite. It also stops `installOpfsSAHPoolVfs()` from calling `removeVfs()` when the pool fails to initialize: `removeVfs()` deletes the pool's directory, so one handle that failed to open (an `UnknownError`, not the lock error) deleted the user's whole mailbox. A failed init now only unregisters the VFS and releases its handles. Keep that part until upstream stops deleting files on a failed init, and validate with `pnpm test utils/mail-engine/opfs-sahpool-init.test.ts`.

`@better-auth__oauth-provider@1.7.4.patch` accepts host-bearing native redirect URIs such as Cursor's `cursor://anysphere.cursor-mcp/oauth/callback`. Better Auth 1.7.4 only allows authority-free reverse-domain schemes (`com.example.app:/callback`). Remove after upgrading to a release that includes https://github.com/better-auth/better-auth/pull/10956, and validate with `pnpm test utils/mcp/oauth-flow.test.ts`.

`@inbox-zero__emulate@0.13.0.patch` makes the Gmail emulator's search honor `OR`. The emulator dropped `OR` tokens and ANDed every term, so `from:a OR to:a` (used by `getThreadsWithParticipant`) and `renewal OR pricing` matched almost nothing, unlike real Gmail. The patch follows Gmail's precedence: `a b OR c` means `a AND (b OR c)`. Remove after upgrading to an emulator release that parses `OR`, and validate with the Relevant context panel on the Cue demo inbox (`pnpm local:start`).

The same patch also lets a Microsoft seed message carry `odata_type` (for example `"#microsoft.graph.eventMessageRequest"`), which the Outlook emulator returns as the message's `@odata.type`. Graph types meeting requests that way and Cue detects Outlook invites by it, so `emulate.playwright.microsoft.yaml` can seed an invite for `mail/calendar-invitation.spec.ts`. Remove after upgrading to an emulator release that supports derived message types (0.14.0 does not), and validate with `PLAYWRIGHT_MAIL_PROVIDER=microsoft pnpm -F inbox-zero-ai test:playwright:emulated mail/calendar-invitation.spec.ts`.
